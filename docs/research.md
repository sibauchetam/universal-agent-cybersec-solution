# Research: 14 статей с AlphaXiv, сформировавших дизайн агента

Источник: AlphaXiv MCP (`POST https://api.alphaxiv.org/mcp/v1`, инструменты `discover_papers` + `get_paper_content`). Поиск вёл по 6 направлениям: CTF/pentest-агенты, SWE-агенты для ремонта уязвимостей, LLM-анализ уязвимостей, форензика логов, эффективность малых моделей, self-verification.

## 1. CTF / pentesting

**Cybench** (arXiv:2408.08926, Stanford) — 40 профессиональных CTF-задач, метрика First-Solve-Time.
- Без подсказок агенты решают 73% задач с FST ≤ 11 минут, но 0% сложнее → тривиальное решать сразу (у нас: fast-path), после неудач — явный план.
- Subtask-guidance prompting: o1-preview 46.8% против 17.5% без декомпозиции → в workflow'ы вшит шаг «план 3–5 шагов».
- Слабое место моделей — многошаговое взаимодействие с окружением, а не знание эксплойтов → чаще запускать bash и проверять гипотезы запуском.

**CVE-Bench** (arXiv:2503.17332, UIUC) — 1000 реальных web-уязвимостей.
- Доминирующий отказ: **insufficient exploration (67.5–80%)** → анти-сдача: минимум разведки (ls/grep/curl) перед любым выводом.
- Team-of-agents с sqlmap: 68% атак через БД против 0% у AutoGPT → SQLi проверять фактическими запросами к живому сервису, не рассуждениями.
- Простые вектора находят чаще «сложных правильных» → сначала очевидное.

**NYU CTF hyperparameters** (arXiv:2508.05674) — Qwen3 28% против Claude 76% на CTF → для нижней границы моделей решают scaffolding и гиперпараметры; категорийная специализация сильная (RE 81%, web 100%) → классифицировать тип задачи первым же шагом.

## 2. SWE-агенты для ремонта уязвимостей

**AgenticRepair** (arXiv:2607.29422) — 73% на SEC-Bench.
- Удаление multi-agent scaffold (одна роль) роняет success с 75% до 30.5% → у нас реализованы минимум 2 роли: исполнитель + критик-ревью/repair-фаза.
- 40% успешных ремонтов требовали правок в нескольких файлах → читать импорты/тесты/соседей перед патчем.

**SWE-Doctor** (arXiv:2607.00990) — 75.7% на SWE-bench Verified.
- Сначала воспроизвести и диагностировать (baseline pytest), потом патчить → для fix-задач baseline запускается механически до цикла.
- Runtime-диагностика ценнее статического чтения.

**Vul4Py** (arXiv:2608.00692) — paired exploit+functional oracles.
- Эксплойт-оракул в одиночку пропускает 12.6% патчей, ломающих функциональность → двойная проверка: PoC больше не срабатывает И оригинальные тесты зелёные.

## 3. LLM-анализ уязвимостей

**VulnLLM-R** (arXiv:2512.07533) — удаление reasoning-компоненты роняет F1 на 37.6% → в промпте аудита требовать пошаговый dataflow-анализ (source → sink), а не паттерн-матчинг.
**OpenAnt** (arXiv:2606.19149) — статическая фильтрация сокращает анализируемые единицы на 96–99% ДО вызова LLM → grep по sink-паттернам — первый шаг workflow аудита; динамическое подтверждение каждой находки; SAST-ложные срабатывания 10–40% → лишний FP дороже пропуска при бинарном скоринге.

## 4. Форензика логов

**RAG для security incident analysis** (arXiv:2603.18196) — локальные модели сопоставимы с облачными (Llama-70B 81% recall); чанкинг теряет 3.6–4.3% логов → читать ВСЕ артефакты полностью.
**AuditBench** (arXiv:2606.10281) — малые модели на ряде задач равны/лучше больших; компактное предобработанное представление логов строго лучше raw → нормализация key=value, сортировка таймстампов до анализа.

## 5. Малые модели

**Notation Matters** (arXiv:2605.29676) — компактные форматы (TOON) дают Qwen3-32B +8–11%, но Mistral-Small-24B падение 89%→53% на одном из бенчмарков → **JSON — безопасный дефолт**, менять формат только после A/B.
**ACM: Agentic Context Management** (arXiv:2607.23809) — выборочная суммаризация: +16% на SWE-задачах, пиковые токены −20% → усечение вывода инструментов с подсказкой «уточните через grep», вербатим-хранение только фактов (пути, флаги).

## 6. Self-verification

**VeriHarness** (arXiv:2607.14167) — **самая применимая**: TypedFields (структурированный feedback `{error_type, expected, actual, file:line}`) вместо сырого traceback: Qwen3-Coder-14B 28%→72%, Llama-3.1-8B 16%→58% → наш `run_pytest` возвращает именно типизированный разбор.
**Self-Authored Verification** (arXiv:2607.24300) — агент, оценивающий себя своими же тестами, завышает себя → верификация только внешними оракулами (данный pytest-сьют, форматные проверки), самописные проверки advisory-only.

## ТОП-5 практик → реализация в `sec_agent.py`

| Практика | Источник | Реализация |
|---|---|---|
| Структурированный error-feedback | VeriHarness | `parse_pytest_feedback()` в `run_pytest` |
| Двойная внешняя верификация | Vul4Py + Self-Authored | механический `verify_deliverable` + repair-фаза; pytest — внешний оракул |
| Фильтр-до-LLM + чтение всего входа | OpenAnt + AuditBench + RAG-IR | workflow'ы audit/forensics |
| Анти-сдача: exploration budget | CVE-Bench + Cybench | workflow-промпты, fast-path только для тривиальных |
| Контекст-гигиена + критик | ACM + AgenticRepair | усечение tool output 7k, repair-фаза свежим циклом |
